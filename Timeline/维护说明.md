## 运行流程

1. `OnEnterAcr` 调用 `BundledTimelineSync.Enter()`。后台先检查随 ACR 包提供的 JSON 并安装缺失文件。Ninja 和 Reaper 共用同一服务。
2. 更新回调调用 `UpdateLoginSession()`。角色登录且 ContentId 有效时，该登录会话首次启用 ACR 会启动一次 GitHub 版本检查；后续每帧回调不会重复发请求。登出事件重置会话标记。
3. GitHub 返回内容必须是有效 PTL JSON，GUID 必须与随包目录中对应文件一致。请求有超时和文件大小上限，下载失败时保留本地时间轴。
4. 本地与云端 `Version` 不一致时，以 GitHub 为准更新。这包括本地版本高于 GitHub 的情况，不应擅自改成“只升不降”。
5. 版本号相同则不覆盖；比较内容时忽略 UTF BOM 和 CRLF/LF 换行格式差异，真正内容不同会在页面提示保留本地内容。状态仍记录磁盘实际字节哈希用于识别后续修改。作者改变时间轴内容后，必须同时更改 `Version`。`.gitattributes` 将仓库时间轴 JSON 的检出换行固定为 LF。
6. 覆盖本地自定义修改前，会在原文件旁生成 `.backup-时间戳-随机值.bak`。临时文件使用 `.luli-tmp-随机值` 后缀，写入前复核目标哈希，避免覆盖期间的文件变化。
7. 文件更新仅影响磁盘。已经加载到 PR 引擎里的轴需要重新加载，不会在战斗中强行重启时间轴。
8. `OnExitAcr` 调用 `Exit()`，取消后台检查并解除登出事件订阅，避免热重载后旧程序集被事件引用。

启动时的随包同步是离线保底：会保留来源不明的已有同 GUID 文件，也不会把已下载的新版本退回较旧随包版本。最终是否更新以登录后的 GitHub 检查结果为准。

## UI 与删除

入口为设置窗口侧栏的“时间轴”。卡片使用 MewUI 现有配色和悬停反馈，宽度足够时两列，否则单列；不要另加字体加载或改变全局样式。

每张卡片显示本地版本、GitHub 版本、状态、检查 / 更新按钮和删除 / 恢复按钮。GUID 放在名称悬停提示中；完整错误信息放在状态悬停提示中。页面读取缓存结果，不在 Draw 中做磁盘扫描或网络请求。

删除需要确认，只删除当前管理的一个已安装文件，不删除 GitHub 源文件、随包文件或其他同 GUID 副本。`setting.json` 中对应 GUID 的 `Disabled=true` 会阻止后续自动重装。恢复会取消此标记、恢复随包副本，再检查 GitHub 版本。

`BundledTimelines` 的每项包含 `FileName`、`Sha256`、`Disabled`。沿用现有 `setting.json`，不要再创建独立时间轴设置 JSON。

## 更新现有时间轴

1. 在 PR 编辑器中完成修改并导出，确认导出文件的 GUID 没有变化。
2. 将内容保存到 `Timeline/NewTimeline` 中对应的原文件名。
3. 更改顶层 `Version`，例如 `1.0.1` → `1.0.2`，其他时间轴不必跟着升版。
4. 运行 `tools/verify-timelines.ps1`，检查 JSON、唯一 GUID、PTL 格式和版本字段。
5. 查看 Git 差异，确保只修改了预期动作、时间点和版本字段，再按用户授权提交、推送到 `main`。
6. 用原始文件 URL 验证 GitHub 上已经是目标版本；在 ACR 时间轴页点击“检查 / 更新”，或下次登录首次启用时自动检查。

现有时间轴只更改 JSON 和版本时，不需要重新发布 DLL。首次安装能力和新增文件目录依赖 ACR 包：新增一份时间轴后需要重新构建并发布 ACR，让用户的随包目录包含它。

## 新增、重命名或移除时间轴

- 新增：把新的合法 PTL JSON 放进 `Timeline/NewTimeline`，确保 GUID 唯一。项目和 Release 使用通配符，会自动打包新文件；需要随新的 ACR 发布。
- 重命名：旧客户端仍使用原来的源文件名访问 GitHub。确需重命名时，要保留旧 GitHub 路径兼容已有客户端，并对新包验证去重，不要直接删掉旧下载路径。
- 移除：删除仓库文件不会自动删除用户的已安装副本。用户可在时间轴页删除；不要增加自动清空整个 PureTimelines 目录的逻辑。

## 构建与验证

在仓库根目录执行：

```powershell
.\tools\verify-timelines.ps1
dotnet build Luli.csproj -c Release -p:GITHUB_ACTIONS=true
.\tools\verify-timelines.ps1 -PackageDirectory "$env:APPDATA\XIVLauncherCN\pluginConfigs\PromeRotation\ACR\Cino"
```

`GITHUB_ACTIONS=true` 在本地此处仅用于关闭 SDK 引用复制钩子，避免构建改写仓库 `lib`。默认编译产物仍写入 Cino 目录。

发布 ZIP 应包含：

```text
Cino/
  LuliReaperPR.dll
  LuliReaperPR.deps.json
  Timelines/
    四份 JSON 文件
```

维护时应验证：首次安装；同 GUID 不重复；版本不一致更新；同版本自定义内容保留；覆盖前备份；删除后重启/检查不重装；恢复；同角色重新登录再检查；网络失败仍能正常使用 ACR；UI 窄窗口布局；MewUI 资源名称与项目 LogicalName 一致。磁盘行为测试请使用临时目录，不要拿真实用户时间轴做删除测试。

PR 使用内存流加载 ACR，`Assembly.Location` 可能为空。定位随包文件时必须保留 `ACR/Cino/Timelines` 回退路径；不要只依赖 DLL 所在目录或 `AppContext.BaseDirectory`。

## 常见问题

| 现象 | 检查位置与处理 |
| --- | --- |
| GitHub 返回 404 | 检查文件是否已推送 main、源文件名是否改变、GitHubTimelineBaseUrl 是否正确 |
| 云端改了内容但不更新 | 比较 JSON 的 Version，版本号相同会保留本地内容 |
| 页面显示 0 份 | 检查 Cino/Timelines 是否随包复制，确认内存加载回退路径仍在 |
| 删除后无法自动安装 | 检查 setting.json 对应 Disabled 标记，使用页面“恢复” |
| 版本更新了但战斗仍按旧轴运行 | 在 PR 中重新加载该时间轴，不要强行重置正在运行的引擎 |
| 时间轴识别成新副本 | 比对 Meta.TimelineGuid；不要按文件名或显示名称作为唯一身份 |
| SDK DLL 被构建改写 | 用上述 GITHUB_ACTIONS 属性关闭复制钩子，仅恢复本次构建产生的已确认差异 |
